# Capabilities rules audit — Easy for everyone

Requested report date: 2026-10-09. Source inspection: 2026-10-10.

Audited public `main` snapshot: `614f927c5734feeba89fea713b122c53cd018a67`. All file/line references below are pinned to that snapshot, not to moving main.

## Rule and interpretation

Source finding: **CAPABILITIES-STRUCTURE.md — rules / Easy for everyone**, using the owner’s verbatim rule supplied with this job:

> **Easy for everyone**: open source, so no step may require a terminal, API key, port, VPN or account the user doesn't already have. Publishing to npm or enabling publication is the owner's decision.

This is a copy and setup-route audit, not a runtime test or a change to policy. A selectable route can violate the rule even when another route is compliant: the row identifies the prerequisite **within that route**, not a claim that every user is blocked. An existing subscription still fails the key part of the rule if setup asks the user to obtain an API key. New developer apps, bot identities and service accounts are not equivalent to signing in to an existing personal account.

The smallest fix is a proposed product/copy change, not a claim that an OAuth flow or managed service already exists. Where the provider cannot support key-free access, the minimum honest fix is to stop offering that route in easy setup and offer a working local/key-free alternative. Merely relabeling a key or hiding its error does not resolve the dependency. No proposal authorizes publishing packages or enabling publication.

## Coverage and method

Reviewed first-run/setup and capability surfaces in `window/src/setup`, Customize, model account setup, computer pairing and gateway reach settings; engine wizard English source copy and its channel setup surfaces; provider auth manifests and relevant registration/setup code; engine browser capability/login copy; bundled skill prerequisites; and the first-run guides under `engine/docs/start`.

Searched for terminal/command prerequisites, API keys and service tokens, ports, VPN/Tailscale, developer-app creation and additional-account requirements. Read surrounding code to distinguish optional existing credentials from required entry. Manifest rows enumerate each key-based provider choice at its canonical label; regional/plan variants share one finding but retain separate line references. Shared wizard copy is cited once per integration rather than duplicating all callers/translations. Findings describe repository copy, not external provider documentation or current provider policies.

Excluded tests/fixtures, internal identifiers and comments, developer-only CLI reference material, agent-executed commands, and runtime implementation errors that do not instruct a user how to enable a capability. This report does not claim that every technical document or every translation was individually audited. The separate One page, Permissions up front and Compatible by default rules are outside this job.

**134 findings**, grouped below. “Disabled offer” means misleading prerequisite copy on an unavailable option, not an executable onboarding blocker. All other rows name the particular active or documented route affected.

## Deliberate non-findings

- Signing in to an account the person already has is compliant; a sign-in button alone is not evidence that a new account is required.
- The optional existing Claude subscription-token import in the window is not itself a demand to create a token; the separate first-run guide that tells people to generate one in a CLI is listed above.
- A terminal tab, an optional CLI shortcut, or a Trunk executing a command is not a requirement that the person use a terminal.
- The custom connector command field launches the program through Branch; its presence alone does not prove a terminal prerequisite. Missing dependency handling should be assessed separately from that field.
- Local inference setup and key-free search are not violations merely because their implementations have optional key fields. Firecrawl’s key-free starter search and optional fetch key are not classified as mandatory-key routes here.
- A displayed endpoint or optional technical port setting is not inherently a required port step; the explicit onboarding port prompt is listed.
- This audit does not prescribe weakening transport authentication or dropping provider authorization to make setup easier.
