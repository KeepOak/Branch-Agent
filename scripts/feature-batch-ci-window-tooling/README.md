# Frozen feature test tooling

This manifest preserves the exact Window toolchain used to verify the replay and transcript export callers: React/React DOM 19.2.8, Vitest 5.0.3, TypeScript 6.0.2, Vite 8.3.0, and jsdom 30.1.1. The production Window manifest and its newer lock resolutions remain independent. Every direct tooling version must equal the corresponding production manifest's exact version or declared range lower bound; a source change requires reviewing this fixture toolchain.

The committed lock preserves that tested dependency graph. Its two workspace links are relative to the repository, and the CI runner installs registry packages into Window's own physical `node_modules/.pnpm`. pnpm creates importer links under the tooling project, so the runner also publishes individual direct dependency links under Window after verifying every installed version and its local target. Before strict checking, the runner generates Kysely types from this checkout's source schemas under canonical artifact ownership. Gateway protocol/client links point to this checkout's canonical engine packages, whose artifacts are built by their package builder. The gate never regenerates this lock or substitutes another checkout's `node_modules`.

Run `node scripts/feature-batch-ci.mjs validate` to check the explicit file list and tooling equivalence without running tests. `node scripts/feature-batch-ci.mjs all` verifies the pinned Node/pnpm runtime, verifies every exact process exception against the public lock, registry metadata, and downloaded SHA512, installs frozen dependencies with lifecycle scripts disabled, builds the two gateway packages, and runs strict checks plus the named engine and Window caller suites. Engine strict checking inherits its production tsconfig for 30 owned production roots and four authored ambient declarations, including their imported type graph; it adds no replacement DOM declarations or diagnostic suppressions. Window strict checking uses four explicit transcript source roots and the pinned TypeScript 6.0.2 compiler with `--ignoreConfig`. The gate requires `RUNNER_TEMP` or an explicit `BRANCH_FEATURE_BATCH_TEMP` scratch directory.

The GitHub workflow runs on hosted Windows, macOS, and Ubuntu with a 15-minute job limit. The committed manifest names exactly 32 engine suites and four Window transcript suites. Each Vitest run uses one worker and the production source aliases/setup. Ubuntu additionally requires hosted Chrome for the live page extraction fixture, with a fresh temporary browser profile. Windows and macOS run the portable browser assertions. No live browser profile, installed desktop app, credentials, private sources, or unrestricted test matrix is involved.
